## Problem Statement

Forage computes the reader's ring — mutuals, follows, one hop out — from the Bluesky
AppView (`js/substrates/lens.js` `ringGraph()`: `app.bsky.graph.getFollows` /
`getFollowers`, paged), remembers nothing across sessions, and has no other source. The
`pds-walker` library (croft-pwa, released `pds-walker-v0.1.0` today) walks the same rings
direct from the data servers, persists them in IndexedDB, and stays honest about stale and
unknown. The owner wants to **experiment** with it in forage before committing: a switch in
settings, under a new **Beta features** section, that sends ring computation through the
walker instead of the AppView. Confirmed scope (owner, 2026-09-08): the switch changes how
the **rings** are computed and nothing else — feed content still comes from the AppView,
and World stays the AppView by definition.

## Reasoning

- **A seam, not a fork.** `ringGraph()` is the one place the graph is read and
  `scopeMembersFor()` its only consumer (evidence below), so the swap is an injectable
  `graphSource` on `createLens` that returns the same `{ me, follows, followers, hopFollows }`
  shape — `rings.js`'s `chain()` and every filter stay untouched. The walker cannot list
  followers (they live in other repos); it CAN say which followees follow back, and forage
  uses `followers` only to derive mutuals (`computeMutuals` = follows ∩ followers), so the
  source supplies `followers := mutuals` and the arithmetic is unchanged. That equivalence is
  the single most important test row.
- **Vendored, per the workspace rule and forage's own shape.** SHARED-CODE.md rule 1 says
  a git dependency pinned to a commit; forage's `gate` job runs with no `npm ci` on purpose
  (zero runtime deps) and serves `js/` unbundled, so the runtime copy is a vendored ESM
  tree under `vendor/pds-walker/` (the library carries `.js` on every import, so the tree
  loads unbundled — proven in croft-pwa's gate), generated by `npm run vendor:sync` from the
  pinned package, and pinned two ways: a manifest of per-file sha256 written by the script
  and checked by `test/vendor.test.js`, and the manifest's source commit checked against
  `package.json`'s pin. When the installed package is present (dev machines, the
  `reference-gate` job), the test also byte-compares vendored to installed — stated in its
  output, never silent. This is D2 of the croft-pwa plan with the tree correction from G5.
- **Device-local, like every other preference.** `js/beta.js` follows `js/ring-scope.js`'s
  read/write/notify shape with key `forage.beta.pdswalker`; never `forage.state`.
- **The switch applies at once.** The graph is cached per lens, so flipping calls
  `lens.forgetRings()` then `syncRingScope()` and re-renders — the same path the ring pill
  already uses (`js/main.js` `ringScope.onChange`).
- **Hermetic e2e.** The harness fences `bsky.network` and the AppView but not
  `plc.directory`; the walker resolves `did:plc` there, so `FENCED` gains it (an unfenced
  host is exactly what the harness's own comment warns against). Test PDS hosts live under
  `*.host.bsky.network` so they are fenced already.

Alternatives rejected: a bundler for forage (D2 rejected by the owner); computing the rings
in a worker (later — the walker is portable, nothing here precludes it); replacing the
AppView path outright (the owner wants to compare).
